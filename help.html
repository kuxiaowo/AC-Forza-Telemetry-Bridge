开始使用

  1. 启动原版 Assetto Corsa 1 或 PC 版 ACC，并进入赛道驾驶界面。两款游戏不可同时运行。
  2. 启动 ACForzaBridge.exe。目标仪表与本机运行时通常使用 127.0.0.1；远程设备则填写其 IPv4 地址。
  3. 让接收端监听与适配器相同的 UDP 端口，默认是 8094，数据格式选择 Forza Horizon / Horizon Dash。
  4. 选择对应的“游戏数据源”，点击“开始适配”。显示“已连接 AC”或“已连接 ACC”后持续发送数据；暂停、回放、退出赛道或共享内存停更时自动发送非比赛状态。ACC 调校菜单也暂停驾驶数据。

程序优先使用手动选择的游戏目录；否则读取 Steam 注册表和 libraryfolders.vdf，并检查 C:～H: 下的标准 Steam 路径。无法唯一匹配时，点击“游戏目录…”选择包含 content/cars 的 AC 根目录。

“模拟测试”只验证发送链路，不代表真实车辆数据。UDP 本身没有接收确认；包数增加只证明本机发送调用成功。

ACC 基础适配

在窗口选择 ACC，或使用 python main.py --headless --game acc --snapshot tmp/acc-status.json。自动扫描 Steam 安装位置，找不到时用“ACC 游戏目录…”选择根目录；不会读取 AC1 的 data.acd。

已通过合成数据、真实 Windows 共享内存和本机 UDP 验证，并确认实车离合方向和下述单车红线学习。其余动态字段及全车型仪表盘验收尚未完成，不能保证所有字段的物理语义已验证。下方完整字段表针对 AC1，ACC 以本节为准。

  • 速度、转速、最高转速、挡位、油门、刹车、圈速、圈数、排名、行驶距离、四轮轮速、胎芯温度及原始悬挂行程使用对应共享内存字段。速度转 m/s，圈速转秒，胎温转 °F。
  • ACC 的 steerAngle 按文档直接为 -1～1，不进行 AC1 的转向锁归一化。仍可使用转向反向和 steer_scale。
  • 离合默认反向，独立配置 acc_invert_clutch=true：ACC 接合值 1 转为 Forza 踏板松开值 0。实车加速记录已确认方向；直接发送会被接收端视为踩下 100%，阻止红线学习。AC1 的离合设置单独保留。
  • 新配置或缺少该字段的旧配置使用修正后的默认值，显式设置仍保留。升级时若沿用旧配置的 false，请停止适配，在 ACC 下勾选“离合反向”后重新开始。
  • 燃油显示共享内存“原值”，不标作升数；比例为 fuel / maxFuel，容量缺失时为零，单位待实机确认。
  • 按当前车型 ID 自动读取资源包中的 CarData，获取怠速、断油转速和前后悬挂限位参考区间；换车后自动匹配，不硬编码单车。最高转速优先取共享内存，缺失时用文件断油值。
  • 限位参考区间为 abs(up.Range − down.Range)，四轮按实时行程除以相应区间后限制到 0～1。区间不要求跨过零点；仅在游戏 EXE 哈希与已核对版本一致时，才补回原生默认值为零的缺省 Range。这是文件提供的参考尺度，不是已验证的全机械行程；调校和缓冲块压缩仍会影响物理含义。没有有效参考时保持零并提示，不填固定有效值绕过检查。
  • 本机离线检查中 56 个 CarData 均解析出断油转速，55 个非 dummy_car 车型资源均取得完整悬挂参考区间。接收端原版算法测试中 55 组模拟断油序列学习成功，55 组低悬挂对照未学习；这不是全车型实机验收。
  • 接收端启用自动红线监测并解锁当前车型，稳定前进挡至少 0.8 秒、油门≥90%、刹车/离合≤5%、四轮参考行程≥10%，观察断油回落。缺少悬挂参考的车型仍受此学习筛选条件阻止。
  • 本机验证：v1.2.1 手动开启 ACC 离合反向后，ForzaTelemetryMonitor V2 beta18.2 将 porsche_991_gt3_r 的红线从 7862.5 学到 9337 RPM。v1.2.2 默认开启该设置；用新版默认值转换真实驾驶记录，隔离回放当前接收端原算法学到 9304 RPM，旧方向对照未学习。这些峰值并非文件中的 9250 RPM 标称断油值，不代表全车型验收。
  • 功率和扭矩仍为零；驱动形式的零值为占位（接收端可能显示 FWD）。动力曲线学习仍未接入。
  • 未经实机标定的加速度、速度向量、角速度、姿态、世界坐标及增压暂不发送，相应 Forza 字段为零。原始值在诊断快照 frame.source_data 中保留；玩家坐标按 carID 匹配 playerCarID，缺失或不唯一时为 null。
  • ACC 车型编号使用独立命名空间，避免与同名 AC1 车型共用接收端档案。PI 仍为兼容占位 1。

原始运动和踏板记录：python -m tools.record_motion --game acc --seconds 60 --output tmp/acc-motion.csv。按直行加速、制动、左右转向、换挡及离合动作分段记录，供方向和单位标定。

接口依据：Kunos Shared Memory v1.8.12 文档，转载来源。不能据此宣称已完成本机游戏版本的实机认证。

车辆解包与计算（仅 AC1）

每次车辆、赛道或会话身份变化时，适配器找到 content/cars/<car_id>，从明文 data 或加密容器 data.acd 读取以下内容；不会修改或重新打包游戏文件。

  • engine.ini：怠速和动力曲线文件名。
  • power.lut：RPM→全负荷扭矩节点，包括原版车允许的负转速启动节点。
  • drivetrain.ini：FWD、RWD、AWD/AWD2。
  • car.ini：从中心到单侧的 STEER_LOCK。
  • suspensions.ini：前后 BUMPSTOP_UP + BUMPSTOP_DN，作为共享内存最大行程缺失时的四轮回退值。

功率/扭矩是静态曲线估算。线性油门缩放不能完整还原涡轮迟滞、增压控制、混动电机、发动机制动、TC、损伤、空气密度和传动损耗。

没有映射或刻意不映射的数据

滑移率、侧偏角、综合滑移、路肩接触、积水、四轮路面震动、手刹、Forza 车辆等级/真实 PI、气缸数、推荐行车线和 AI 刹车差值保持为零或明确占位。AC 虽还提供刹车温度、轮胎磨损、DRS、ERS/KERS、损伤和旗帜等数据，但 Horizon Dash 当前对应布局没有接入这些字段。

归一化悬挂沿用现有的“当前行程÷最大行程”算法；它不证明每辆模组车都严格符合 Forza 的 0=全伸、1=全压语义。

常见问题

一直显示等待游戏

确认所选数据源与运行的 AC1 / ACC 一致，且已进入赛道。两款游戏不可同时运行，启动器或主菜单不代表有效驾驶数据。

提示无法唯一匹配游戏目录

点击“游戏目录…”，选择实际运行的 Assetto Corsa 根目录，不要选择某一辆车的目录。

仪表完全没有数据

确认 IP、端口一致，接收端选择 Horizon Dash；远程设备还需检查 Windows 防火墙和局域网隔离。

离合或转向方向相反

AC1 和 ACC 默认都需要“离合反向”，各自保存配置。ACC 正常行驶时适配器应显示离合 0%；若为 100%，请停止适配、勾选“离合反向”后重新开始。不同接收端或控制配置若表现相反，可单独调整。

功率与车辆标称值不同

当前显示的是根据基础全负荷曲线和油门估算的发动机功率，不是轮上实测功率；涡轮和混动车差异会更明显。
